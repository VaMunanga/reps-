# Focus API contract

Same-origin JSON at `api/focus/index.php?action=ACTION`. GET reads, POST mutations with JSON body and `X-CSRF-Token`. Responses include `ok`, `serverTime` (ISO UTC). Successful authenticated responses also include `accountTotals:{focusedMinutes,reps}`, aggregating confirmed solo and group work once; anonymous/logout responses omit it. These totals are displayed separately from retained device history. Errors: `{ok:false,message}` with appropriate HTTP status. Never include passwords, tokens except newly rotated invite token, or another member's personal task. IDs are strings in JSON. User name is a chosen display name, not an asserted verified identity.

- GET `bootstrap`: `{user:null|{id,name,email},csrf,recoveryAvailable,groups:[{id,name,ownerId}]}`. Anonymous bootstrap still issues session/CSRF token.
- POST `register` `{name,email,password}` and `login` `{email,password}`: same shape as bootstrap, rotated session and CSRF.
- POST `logout`: anonymous bootstrap shape.
- POST `reset_request` `{email}`: generic message; HTTP 503 with accurate setup message if recovery unavailable.
- POST `reset_password` `{token,password}`: generic success; revoke account sessions.
- POST `group_create` `{name,timezone}`: `{groupId}`. Creator becomes member and owner.
- POST `invite_rotate` `{groupId}`: `{inviteToken}`. Owner only; previous token revoked. Link is `focus.html#invite=TOKEN` (fragment avoids server/referrer logging).
- POST `invite_join` `{token}`: `{groupId}`.
- GET `group_view&groupId=ID`: `{group:{id,name,ownerId,timezone,leaderboardEnabled},membership:{shareProgress,showRanking},schedule:null|{id,task,startsAt,focusMinutes,breakMinutes,rounds},template:null|{task,focusMinutes,breakMinutes,rounds},participants:[{name,state,focusedMinutes,reps}],leaderboard:[{name,focusedMinutes,reps}],me:{state,focusedMinutes,reps,participating}}`. Participants includes self and members who explicitly share progress. Ranking includes current members opted in only; disabled group leaderboard returns empty list. `state`: Waiting/Focusing/On break/Paused/Finished. Group schedule includes `serverTime` in outer response; clients derive remaining time locally using measured offset.
- POST `group_schedule` `{groupId,task,startsAt,focusMinutes,breakMinutes,rounds,saveTemplate}`: `{scheduleId}`. Owner only; reject replacing a not-yet-finished schedule. StartsAt is UTC ISO, timezone is display only. Focus 1–180 min, break 1–60 min, rounds 1–8; future start no more than 30 days away.
- POST `group_preferences` `{groupId,shareProgress,showRanking}`: `{ok:true}`. Owner may additionally set `leaderboardEnabled`.
- POST `group_leave` `{groupId}`: `{ok:true}`. Leave stops personal participation/access; owner must reject if other members remain (explain clearly), otherwise archive the empty group without deleting history.
- POST `participation` `{groupId,scheduleId,operation}` where operation is join/heartbeat/pause/resume/leave: `{ok:true}`. Only personal participation changes. Every heartbeat is server timed, max confirmed gap 30 sec, UI sends each 15 sec while participating. A pause or gap forfeits the current round's rep; partial confirmed minutes retained. Transactional account lock prevents overlaps across group/solo intervals. Reads also finalize eligible completed rounds idempotently.
- POST `solo` `{operation,clientId,durationMinutes}` where operation is start/heartbeat/pause/resume/end: `{ok:true,totals:{focusedMinutes,reps},state:'running'|'paused'|'ended',deadline?:ISO_UTC}`. Authenticated only; server starts and caps own session timestamps; no client-supplied interval credits or legacy imports. Browser aligns a matching running session to the accepted deadline using response serverTime; startup remains immediate. Start requires duration 1–180. One active source per account; competing active group/solo source rejected with a useful message. Local solo timer still functions when API offline; unconfirmed time cannot enter server rankings.

Database names/functions are implementation choices, but PHP endpoint and browser controller must preserve these shapes. Use opt-in defaults for both sharing and ranking, Monday-start leaderboard weeks in saved group IANA timezone, fixed after participation. All mutations authorize membership/ownership server-side. No fake participants or local group persistence.
